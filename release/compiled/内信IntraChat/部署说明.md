# 内信 IntraChat · 编译后免安装运行包

本包已完成全部编译，且依赖均为纯 JS（已去除原生模块 bcrypt，改用 bcryptjs），
`node_modules` 已随包携带，**无需 npm/pnpm install、无需重新构建**。
目标机只需：Node.js 20+ 与 MySQL 即可运行。

> ### ⚠️ 启动方式（务必先看，否则会报 system32 错误）
>
> **必须“全部解压”后，进入解压出来的文件夹，双击里面的 `start.bat`。**
> 具体：右键 `内信IntraChat-运行包-v2.zip` → 选择「全部解压」→ 选一个普通目录（如
> `D:\intranet-im`）→ 打开该文件夹，确认能看到 `dist-server` 文件夹和 `start.bat` →
> 双击 `start.bat`。黒色窗口会先打印一行「脚本所在目录（APP_DIR）= D:\intranet-im\」。
>
> **绝对不要做以下操作**（都会导致找不到入口）：
> 1. ❌ 在压缩包预览窗口里直接双击 `start.bat`（文件其实没解压到真正目录）。
> 2. ❌ 自己开 CMD / PowerShell / 运行框，手敲 `node dist-server\server.js` 之类的相对路径命令。
> 3. ❌ 用旧版本残留的快捷方式或旧文件夹里 `start.bat`（可能仍是旧包）。
>
> **如果还报** `Cannot find module 'C:\Windows\system32\dist-server\server.js'`：
> 说明启动 Node 时工作目录是 `system32`，即上面第 1 或 2 条。请换成「全部解压后双击 start.bat」，
> 并把黒窗口里「脚本所在目录（APP_DIR）=」那行发回来，即可确认真实运行位置。
> 本版 `start.bat` 已内置绝对路径 + 自定位，只要是这样双击启动，绝不会再出现 system32 路径。

## 目标机准备（一次性）
1. 安装 Node.js 20+ LTS：https://nodejs.org
2. 确保 MySQL 已启动（默认 3306）。数据库**无需手动建**，首次启动自动创建并建表。

## 三步启动
1. 把本文件夹拷到目标机，如 `D:\intranet-im`。
2. 用记事本打开 `.env`（或首次运行会自动从 `.env.example` 复制），填写：
   - `DB_HOST`、`DB_PORT`（默认 127.0.0.1 / 3306）
   - `DB_USER`、`DB_PASSWORD`：你的 MySQL 账号密码
   - `JWT_SECRET`：改成一长串随机字符
   - `MAX_UPLOAD_MB`：默认 100
3. 双击 `start.bat`（或 PowerShell 运行 `start.ps1`），看到：
   `✨ Server running at http://localhost:5000` 即成功。

## 使用
- 聊天 / 登录：`http://localhost:5000`
- 管理后台：`http://localhost:5000/admin`
- 初始管理员：`admin / Admin@123456`（**首次登录强制改密**）

## 局域网内其他电脑访问
把 `localhost` 换成这台机器内网 IP，并在 Windows 防火墙「入站规则」放行 TCP 5000。

## 常驻后台 / 开机自启（可选，任选其一）
- **pm2**（简单）：
  ```powershell
  npm i -g pm2 pm2-windows-startup
  pm2-startup install
  pm2 start dist-server/server.js --name intrachat
  pm2 save
  ```
- **NSSM**（注册为 Windows 服务，更适合长期服务器）：
  ```powershell
  nssm install IntraChat "C:\Program Files\nodejs\node.exe" "D:\intranet-im\dist-server\server.js"
  nssm set IntraChat AppDirectory D:\intranet-im
  nssm set IntraChat Start SERVICE_AUTO_START
  nssm start IntraChat
  ```

## 上传文件失败排查（Windows）

本版上传已做加固：前端按 **2MB 分片**逐片直传（单片超时 60s、失败指数退避重试 4 次），
后端**原子写盘 + Windows 文件锁/杀软占用重试 + 合并幂等**。若仍提示「上传中断/未能传输完成」，按以下顺序排查：

1. **不要装在受保护目录**：不要放到 `C:\Program Files\` 或 `C:\Windows\`（UAC 会拦截写入）。
   建议 `D:\intranet-im` 之类普通目录。程序需对自身目录及 `uploads\` 有读写权限。
2. **杀毒软件/Windows Defender 实时保护**：会锁定刚写入的分片文件导致中断。把程序目录
   （如 `D:\intranet-im`，尤其 `uploads` 子目录）加入杀软「排除项/白名单」。
3. **磁盘空间**：确认目标盘剩余空间足够（单文件 ≤100MB，分片合并时短暂占用约 2 倍）。
4. **看服务端黑窗口日志**：真正原因会打印在运行 `start.bat` 的窗口里，例如：
   - `服务器无写入权限：...uploads` → 目录权限/杀软问题（对应上面 1、2）。
   - `服务器磁盘空间不足` → 清理磁盘。
   - 窗口直接关闭/重启 → Node 进程异常，请确认使用的是本最新包且 Node.js 为 20+。
5. **访问地址**：浏览器请用 `http://本机内网IP:5000` 或 `http://127.0.0.1:5000`，
   不要经过 IIS/Nginx 等反向代理（如确需反代，需把 `client_max_body_size`/请求超时调大并允许 100MB）。
6. **确认跑的是新包**：旧版本前端是 4MB 分片且无重试；本版上传时进度按 2MB 跳动即新版本。

> 聊天文件仅提供下载、不做在线预览（需求基线）。头像限制 2MB（jpg/png/webp）。
